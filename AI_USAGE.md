## Steps

2. **feat(backend): scaffold .NET 8 Web API** — `backend/SchoolAdmission.Api` (net8.0) + `SchoolAdmission.sln`, Kestrel on `http://0.0.0.0:8080`, `GET /health` -> 200 `{"status":"ok"}`, Swagger UI. Connection string comes from env var `ConnectionStrings__Default`, and the app fails fast if it is missing. A design-time factory lets `dotnet ef` run without a DB. 4. **feat(docker): backend Dockerfile + docker-compose** — multi-stage `backend/Dockerfile` (build `sdk:10.0`, runtime `aspnet:8.0`, port 8080, non-root `$APP_UID`). Root `docker-compose.yml`: `db` = `postgres:16-alpine` with named volume `pgdata` and a `pg_isready` healthcheck (not published to the host; a local Postgres 18 already uses 5432). `backend` depends on `db` being healthy, with env `ConnectionStrings__Default` and `HOLD_DURATION_SECONDS=600`. EF migrations are applied at startup with a short retry. Verified with `docker compose up --build`: `GET /health` returned 200 and the tables and indexes exist.

5. **feat(classes): POST /classes, GET /classes, GET /classes/{classId}** — contract shapes exactly. Counting lives in one place (`SeatCounts`): held = HELD with expiresAt > now, confirmed = CONFIRMED, available = total − held − confirmed. Validation: body required, name required and non-blank (trimmed, max 200), totalSeats required and > 0 → 400. Malformed JSON or wrong types → 400 via the framework, and missing Content-Type → 415. All errors are problem+json with a human-readable `detail`. Unknown class → 404. Verified with curl in Docker, including seeded HELD/expired/CONFIRMED/CANCELLED holds.
   - Self-caught bug: the first version projected into a positional record, which EF can't translate when `OrderBy`/`Where` is applied after it, so the GETs returned 500. Switched to member-init projection.
6. **feat(holds): POST /classes/{classId}/holds** — `X-Student-Id` checked (present, single value, exactly 17 ASCII digits) → 400. Unknown class → 404. Inside a transaction: `SELECT * FROM classes WHERE id = … FOR UPDATE`, then recount → 409 if the student already has an active hold, 409 if the class is full, else insert HELD with `expiresAt = now + HOLD_DURATION_SECONDS` → 201 with Location `/holds/{id}`. `HOLD_DURATION_SECONDS` is parsed at startup (default 600; a non-positive or non-integer value fails startup). The clock is an injected `TimeProvider`, ready for tests.
   - Partial unique index: the user asked to add `(classId, studentId) WHERE status IN ('HELD','CONFIRMED')` via a migration. It already exists from step 3 as `ux_holds_active_student_class` on `(student_id, class_id)`, which enforces the same thing, so no duplicate migration was added.
   - Design decision: an expired HELD row still matches the partial index (the index can't use `now()`), so before inserting, the student's expired HELD row in that class is set to CANCELLED under the class lock. Flagged to the user.
   - Verified in Docker: all 400/404/409/201 paths. 40 concurrent students on 5 seats → exactly 5×201, 35×409. One student sending 15 concurrent requests → exactly 1×201. No 500s.
7. **refactor(backend): layered structure, DTOs, error middleware** — minimal-API endpoints replaced by `Controllers/` (Health, Classes, Holds) → `Services/` (`IClassService`/`IHoldService` in `Services/Interfaces/`, typed `NotFound`/`Conflict`/`BadRequest` exceptions in `Services/Exceptions/`) → `Data/`. Entities moved to `Models/` (plus the `ClassSeatSummary` read model). `DTOs/` holds request/response records, `ErrorResponse`, and `MappingExtensions` (`ToResponse`/`ToCreatedResponse`, no AutoMapper). Request validation uses data annotations (`[Required]`, `[StringLength]`, `[Range]`; `[RegularExpression("^[0-9]{17}$")]` on the `X-Student-Id` header). `Middleware/ErrorHandlingMiddleware` turns AppExceptions, framework 4xx, unhandled exceptions (500, details only in logs) and any body-less 4xx (unknown route 404, 405, 415) into `ErrorResponse {statusCode, message, errors, timestamp}`. `ValidationErrorFactory` does the same for model-state 400s with readable messages. 2xx bodies are not wrapped. Queries are LINQ, except the `SELECT … FOR UPDATE` lock, which EF Core 8 can't express in LINQ.
   - Kept the user's new `/health` message.
   - Migrations: entity namespace `Domain` → `Models` updated in the migration designer/snapshot; `dotnet ef migrations has-pending-model-changes` → none.
   - Verified in Docker: 2xx shapes and Location headers diffed against a pre-refactor baseline (identical); all 400/404/405/409/415 paths return ErrorResponse; stopping the DB gives a 500 ErrorResponse; 40 students on 5 seats → 5×201, 35×409.
   - Behavior notes: error bodies changed from problem+json to ErrorResponse, as requested. A repeated `X-Student-Id` header now says "must be exactly 17 digits" instead of "must be sent once" (still 400).
8. **feat(backend): GET hold with derived expiry** — `GET /holds/{holdId}` → `{holdId, classId, status, expiresAt}`, 404 for an unknown id. Status is derived with `Hold.IsExpired(now)` (HELD and `expiresAt <= now` → `EXPIRED`); the stored status is never changed on read. Verified HELD / EXPIRED (stored row still HELD, class counts exclude it) / CONFIRMED past expiresAt (stays CONFIRMED) / CANCELLED / unknown / non-guid id.
   - Note: the CLAUDE.md contract line still lists `HELD|CONFIRMED|CANCELLED` for this endpoint. Followed the user's step instruction (derived EXPIRED, consistent with rules 2 and 8).
9. **feat(backend): confirm (idempotent) and cancel** — `POST /holds/{id}/confirm` and `DELETE /holds/{id}`, both requiring `X-Student-Id` (400). Both follow the same pattern: an unlocked ownership read (404 unknown, 403 another student's hold), then a transaction that locks the class row with `FOR UPDATE` (same lock order as hold creation), re-reads the hold, and decides.
   - Confirm: CONFIRMED → 200 unchanged (idempotent); CANCELLED or EXPIRED → 409; live HELD → CONFIRMED (+ `confirmed_at`) → 200 `{holdId, status}`.
   - Cancel: CONFIRMED → 409; CANCELLED or EXPIRED → 204 no-op (an expired hold is left as stored HELD so it keeps reading EXPIRED); live HELD → CANCELLED → 204 with no body.
   - Verified in Docker: every status path. 20 parallel confirms → 20×200 with confirmedSeats +1 once. 10 confirm-vs-cancel races → always a consistent pair (confirm 200 + cancel 409 → CONFIRMED). No 500s.
10. **feat(backend): GET /me/holds** — header required (400). Returns all of the student's holds, any status, newest first (`created_at DESC, id DESC`), each `{holdId, classId, className, status, expiresAt}` with derived EXPIRED; LINQ with `Include(Class)`. Verified ordering, HELD/CONFIRMED/EXPIRED mix, isolation between students, empty list `[]`, and missing/invalid header.
