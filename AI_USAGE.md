## Where AI made mistakes and how I caught and fixed them

1. **Backend template layout.** The first backend code generated by Claude did not follow a proper project structure. It put the files and all the endpoints into a single file, with no Controllers, no Services, no DTOs and no service interfaces (IServices). I noticed this when I reviewed the generated code: it was not separated by responsibility, so it was hard to read, extend and test. I refactored the layout myself into separate layers: Controllers for the endpoints, Services (with IServices interfaces) for the business logic, and DTOs for the request and response models.

## What I wrote or decided myself

I designed and decided the core backend logic myself:

- **Hold time calculation:** how the hold duration is calculated for a class application (`HOLD_DURATION_SECONDS`, `expiresAt`) and when a hold counts as expired.
- **Status updates:** how the status moves between HELD, CONFIRMED, EXPIRED and CANCELLED.
- **Seat calculation:** how total, held, confirmed and available seats are calculated for each class.
- **Hold and confirm:** the rules for creating a hold and for confirming it, including the cases where confirm must be rejected.
- **Cancel and payment:** how cancelling an application works and how the simulated payment (button press = success) is handled.
- **Concurrent requests:** how the system handles multiple API calls arriving at the same time for the same seat, so that held + confirmed never exceeds totalSeats.

I also reviewed the AI-generated code and corrected it where it did not match these decisions.
